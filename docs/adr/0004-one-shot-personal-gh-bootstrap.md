# ADR-0004: 一次性个人 gh 身份引导实验

**日期**：2026-10-04<br>
**状态**：accepted（限次实验例外，附固定期限与终止条件）<br>
**决策者**：仓库所有者（用户）与 Harness Steward

## 背景

[ADR-0002](0002-github-app-unattended-identity.md) 已接受 GitHub App 作为长期无人值守身份，App 配置、私钥隔离与 `main` 保护仍未验证，App 发布入口不可用。在此之前，需要回答一个前置问题：在单机、单 Worker、人工监督的边界内，一台确定性的本地编排器能否诚实地串联「已合并 Plan PR → 固定配置 Worker → 候选核验 → 独立只读审查 → Delivery PR → 对应 CI → 条件式合并」的完整链条。为回答它，用户于 2026-10-04 授予一次限次例外：允许编排器使用现有个人 `gh` 登录态完成机械 GitHub 操作。

## 决定

本次实验（`agent-delivery deliver` 单次编排入口）允许：

- 使用本机个人 `gh` 登录态推送交付分支、创建或定位 Delivery PR、查询 CI 与合并；
- 在**全部质量门禁满足后**自动合并本次清单内的 harness 开发 PR、Plan PR 与 Delivery PR；
- 创建一张专用跟踪 Issue 发布脱敏进度与结论（Issue 不构成执行授权）。

## 明确边界

1. **这是一次性例外**：不声称个人 `gh` 身份已成为正式无人值守身份；ADR-0002 的 App 路线不变，不因本实验取消或推迟。
2. 个人 `gh` 登录的实际权限可能大于本次授权；操作范围由外层控制约束（限目标仓库、限本次清单 PR），不能宣称账号权限已被硬性缩小。
3. 不向 `agent-run --publish` 增加个人 Token 后门；App 发布接口的门禁（`AGENT_APP_KEY_ISOLATION_VERIFIED`、`AGENT_MAIN_PROTECTION_VERIFIED`）保持不变。
4. 不设置虚假的 App、隔离或分支保护验证标记；本次不修改仓库保护设置。
5. 自动合并的前置门禁（全部满足才合并）：安装来源与获准源码/wheel 一致；Plan PR 已合并进 `main`；`agent-run` 退出码 0 且运行记录证明 Worker 已确认停止、产出在授权范围内；独立只读审查回执 `pass` 且绑定同一 head；该 head 的必需 CI 检查真实成功；远端分支 head 等于已审查 head。任一缺失、取消、跳过或不确定都不得合并。
6. 期限：本实验自 2026-10-04 21:59（UTC+8）起四小时内有效；到期不续，不新开工单，只做有界清理与汇报。

## 后果

- 编排器可以诚实地验证「机械步骤自动化」这一层，但验证结果**不外溢**：GitHub App 无人值守线路、真实异常停止、操作系统级隔离与账单硬上限仍未验证，也不因本实验标记为已验证。
- 个人身份与自动化行为在本实验中混同，这恰是 ADR-0002 要在长期方案中消除的问题；实验结束即停。
- 实验结论（无论成败）记入脱敏简报与跟踪 Issue，历史 ADR 与人工交付记录不改写。
