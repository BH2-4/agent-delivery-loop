# ADR-0001: 使用 Python 编写本机执行器

**日期**：2026-09-28<br>
**状态**：accepted<br>
**决策者**：仓库所有者与 Steward

## 背景

v0 在一台受信任的本地主机上工作，由 `agent-watch` 发现已授权任务，再通过唯一入口 `agent-run` 执行。执行器需要读取 GitHub 状态、校验 Work Order、管理本地进程与 worktree，并留下可恢复的运行记录。仓库所有者已选择 Python 作为实现语言。

## 决定

`agent-watch`、`agent-run` 及其共用的确定性逻辑使用 Python 编写，提供本机 CLI 入口。Claude Code 作为外部执行进程运行；Python 负责授权校验、隔离、结果核对和 GitHub 操作。具体 Python 版本、依赖管理工具和启动调度配置留待实现时确定并锁定。

## 考虑过的方案

### Shell 脚本

- 优点：本机启动方便，依赖少。
- 缺点：状态机、结构化数据校验、错误分类和跨进程恢复会逐渐难以维护。
- 未选择的原因：执行器不只是调用几个 CLI 命令，还要承担可审计的控制逻辑。

### Node.js / TypeScript

- 优点：GitHub 生态和类型工具成熟。
- 缺点：需要为本机执行器引入另一套运行时和打包约定。
- 未选择的原因：用户已选择 Python，且 v0 的单机控制流程用 Python 足够直接。

## 后果

### 正面

- 两个命令可以复用同一套 Work Order、授权和运行状态逻辑。
- Python 可以明确区分可重试的 GitHub 操作与不可盲目重试的 Agent 执行。

### 代价

- 需要锁定解释器与依赖版本，提供本机安装和诊断命令。
- Python 进程退出后仍须依靠持久运行记录判断任务状态；语言本身不提供去重保证。

### 风险与应对

- 如果后续加入其他 Worker，应增加受控适配层；不得让每个 Worker 自行实现授权规则。
