# ADR-0005: 审查证据契约与只读查询可靠性（第二轮限次实验）

**日期**：2026-10-05<br>
**状态**：accepted（限次实验例外，固定期限与停止条件）<br>
**决策者**：仓库所有者（用户）与 Harness Steward

## 背景

[ADR-0004](0004-one-shot-personal-gh-bootstrap.md) 的实验已于 2026-10-04 结束（Issue #13 留档），暴露两个结构性问题：

1. **审查资料包无法承载验收证据**：资料包只含 Work Order、Skill 与 diff；当工单要求文档陈述门禁语义或决策边界时，诚实的只读审查员在包内无从核实，只能返回 `blocked`（三次一致）。
2. **GitHub 只读查询不可靠**：无认证读取经共享代理出口出现间歇 TLS 握手超时与最终 403 限流；编排层无分类、无重试、无缓存，导致已完成的真实审查被迫重复调用模型。

## 决定（本轮工程范围）

### 证据契约

- Work Order v1 新增**可选**字段 `review_evidence`（1–20 条 `{path, ref, purpose}`）：`path` 为仓库相对普通文件路径（拒绝通配/越界），`ref` 为完整 40 位十六进制提交 SHA，`purpose` ≤500 字符。缺省该字段的旧工单行为不变。
- 资料包新增 "Pinned baseline review evidence" 区：按 `ref:path` 读取固定版本 blob（经 `core.useReplaceRefs=false` 的统一入口），记录 git blob id 与嵌入文本 SHA-256，明确标注为**主线依据**而非候选内容；check-review 重建同一快照逐字核对。
- 边界：单文件 ≤32 KiB、证据合计 ≤48 KiB、整个上下文 ≤96 KiB（由 64 KiB 上调，仍禁截断）；拒绝符号链接、子模块、非普通文件、UTF-8 之外内容。
- Worker 开工前执行确定性**证据就绪检查**（`check-evidence` / deliver 内联）：固定 ref 无法解析、路径缺失或超限时先停止，不浪费 Worker 调用。
- 职责分离：外层程序核验授权/SHA/摘要/退出码/CI；审查 Agent 只判断候选内容与所供依据是否一致，不重复联网证明程序事实。

### 只读查询可靠性

- `GitHubClient` 按实际响应分类：瞬时网络错误（URLError/超时/5xx）最多两次有界重试（2s/8s，单次超时 30s，总预算 120s）；明确限流（`X-RateLimit-Remaining: 0` 或正文标记）在预算内等待一次；401/403 非限流、404 等 4xx 立即失败，绝不重试。
- 固定 ref 的 `content()` 结果（已核验 blob sha）可缓存复用；Plan/PR/main 等可变状态在关键动作前重新查询。
- 审查进程完成后才发生网络复核失败时，编排记录先落 `review_completed_pending_check`（含捕获退出码与回执路径）；网络恢复后用 `verify-review` **复核同一回执**，不重新调用模型。
- 指定 `--proxy` 时同时清理 `ALL_PROXY`（含小写）避免被其覆盖。推送/创建 PR/合并不适用盲目重试，结果不确定先查实际状态。

## 本轮例外与期限（不延长 ADR-0004）

- 一次性使用现有个人 `gh` 登录态；范围仅限本轮修复 PR、新 Plan PR、新 Delivery PR 的创建/更新与门禁满足后的自动合并；一张跟踪 Issue。
- 期限：2026-10-05 01:25 至 05:25（UTC+8），到期仅做有界清理与汇报。
- 唯一新真实工单；每开发单元与工单最多两轮有效返修；不重跑 WO-PILOT-001/002、WO-DOC-TRIAL-001。
- 个人 `gh` 权限可能大于本轮授权；不声称已实现硬隔离。GitHub App 长期路线（ADR-0002）不变；不设置任何虚假验证标记。

## 后果

- 工单验收所需证据随授权固定版本进入资料包，审查员可在包内完成核对；不放宽任何门禁，也不以"约定"改称事实。
- 上一轮的 `blocked` 根因被结构性消除，而非被绕过；三次旧审查记录保持原状。
- 本轮修复、审查、安装与试跑结果仍不证明：正式 App 无人值守线路、OS 级凭据隔离、真实 Claude 全部异常停止路径、账单硬上限或部署。
