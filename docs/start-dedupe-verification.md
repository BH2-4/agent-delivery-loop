- 实验原型的未修改基线 T1–T3 各观察两个启动；最终隔离候选 13/13 通过。
  本轮读取协议、原始逐场景断言和早期候选记录，不将原型结果归给产品。
- 针对性测试最初因产品缺少 `execution.py` 无法导入；随后在原产品
  `runner.py` 的未修改字节上执行行为断言，正常请求在三个新状态目录累计启动
  3 次，且启动前退出/缺回执路径再次进入模型入口。原文件未修改。
- 首轮既有回归 2 个失败、8 个错误，原因是既有测试夹具仍走匿名入口、没有
  共享存储替身。仅补夹具与显式合成身份，原断言不变；复查通过。
- 真实 API 首轮在准备启动未知窗口时，创建 tree 的写请求先返回未知结果。
  未进入预定窗口，断言失败；没有模型调用，10 条合成 refs 核对清理。
  只针对剩余窗口重测并先固定领取记录，剩余三项通过；不将它称为已复现
  “服务端写了启动 ref 后实际 TCP 响应丢失”。
- 验证脚本的一次命令转义错误导致误启动整轮，已中止；按六条准确 ref/SHA
  快照核对同一合成命名空间后清理，独立保留清理记录。
- Windows 当前 Claude `2.1.181` 低于门槛，未拿它发模型请求。官方 npm 包
  `2.1.289` 下载到本轮 work，核验完整性后在 WSL 使用，没有修改全局安装。
  模型控制器读取 WSL stderr 时产生字符集解码警告；实际退出码 0、结构化
  回执从独立文件读取并核对，未因此重跑模型。
- 模型冒烟之后补充了截断/非 UTF-8/错误状态/缺 SHA 响应分类和旧本机记录
